# 경쟁 앱 페이지 양식 (product/competitors/<app>.md)

> `wiki/product/competitors/<app>.md` 작성용. **기능 목록이 아니라 "왜 성공했는지 / UX / 락인 / 빈틈"** 을 본다. 아래 블록 복사.

```markdown
# 경쟁: <앱 이름>

> 한 줄: <무엇으로 이기는 앱인지>

## 왜 성공했나
- <핵심 성공 요인 — 기능이 아니라 이유>

## UX 특징
- <사용자가 좋아하는 경험·흐름>

## 락인 요소
- <떠나기 어렵게 만드는 것: 데이터·습관·네트워크>

## 약점 / 빈틈 (차별화 기회)
- <불만·미충족 지점 → 우리 기회>

## 근거 원본
- raw/market-research/... · [[sources/...]]

## 연결
- 시장: [[product/markets/...]] · 불만: [[product/pain-points/...]] · 가설: [[product/hypotheses/...]]
```

## 채우는 법
- "무슨 기능이 있다"가 아니라 "왜 그게 통했나"를 적는다.
- 약점/빈틈은 [[product/hypotheses/...]] 가설의 씨앗이 된다.
