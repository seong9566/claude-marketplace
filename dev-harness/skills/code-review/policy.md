# Code Review 공통 정책

Claude Code판과 Codex CLI판이 **공유하는 정책**이다. 엔진이 무엇이든 게이트·스탠스·확신도·심각도·출력 형식·수렴 판단·게시는 같다. 각 `SKILL.md`는 **엔진 호출 방법만** 다르게 적고 이 파일을 참조한다.

> **정책을 고칠 때는 이 파일만 고친다.** `~/.codex/skills/code-review/policy.md`는 이 파일로 향하는 심링크다 — 양쪽에 손으로 이중 반영하던 방식은 2026-07-27에 폐지했다(한쪽만 고쳐 조용히 어긋나던 문제).

## 게이트 — 진행/스킵
- **내가 만든 PR은 항상 리뷰한다.** 동작 변경 여부·diff 크기·문서/설정 여부와 무관하게 스킵하지 않는다(순수 리팩터·문서 PR도 리뷰). 리뷰 verdict가 곧 "이 PR을 자동 반영해도 되는가"의 판별 신호라 모든 PR에 verdict가 남아 있어야 하고, **발견이 없으면 "무발견"도 유효한 신호**다.
- **적격성**: closed·draft·이미 내가 리뷰함 = 스킵. 그 외 스킵 사유는 없다.
- 스킵 시 코멘트 달지 않고 사유만 사용자 요약에 한 줄.

> 정본은 전역 CLAUDE.md §"PR 생성 후 자동 코드 리뷰". 2026-07-22 사용자 결정으로 **이전의 동작-변경 게이트·trivial 스킵·회색지대 규칙은 폐지**됐다. 되살리지 말 것.

## 적대 스탠스 + focus
- 스탠스: "이 변경이 아직 배포되면 안 되는 가장 강한 이유를 찾아라. 좋은 의도·부분 수정에 점수 주지 마라. happy path만 되면 그것이 약점이다."
- attack-surface 우선순위: auth·권한·테넌트격리 / 데이터 손실·손상·비가역 상태 / 롤백·retry·부분실패·멱등성 / 레이스·순서·재진입 / empty·null·timeout·degraded 의존성 / 버전skew·스키마drift·마이그레이션 / 관측성 공백.
- **focus 라우팅** — Risk Score(작성자 PR 템플릿 + diff 통계: 보안30·스코프20·Breaking20·테스트15·마이그레이션15)와 변경 경로로 focus만 정한다(패스 수는 항상 1):
  - `auth`·로그인·권한·결제·`secrets`/`.env` → `"auth·인가·secrets·injection 집중"`
  - DB 스키마·마이그레이션 → `"스키마 drift·마이그레이션·롤백 안전 집중"`
  - 500줄+ → `"file-by-file로 검토"`
  - 저Risk → focus 없음(기본 adversarial)

## 확신도 · 그라운딩
- 발견별 확신도 0-1에서 **≥0.8만 채택**(<0.8 드롭).
- 없는 파일/라인을 지어내지 않는다. 추론이면 명시하고 확신도를 낮춘다.
- **미커밋 오탐 차단**: 발견이 `gh pr diff <PR#> --name-only` **밖 파일**이면 범위 밖으로 표기하고 되돌리지 않는다(엔진이 맥락 밖 워크트리의 미커밋 변경까지 읽는 실측 문제 — 로컬 baseUrl 오버라이드 등은 의도된 설정).
- **기존 결함 귀속**: 발견이 **base에서도 재현**되면 이 PR 귀속이 아니다 — `기존 결함(이 PR 귀속 아님)`으로 표기하고 심각도는 **이 diff가 만든 악화 폭만** 평가한다(실측 예: 다크 상호작용 대비가 PR 이전부터 미달이고 이 PR 기여는 1.43→1.28 소폭 악화였는데 사이클 2·3이 같은 발견을 [high]로 반복). 귀속은 추정하지 말고 실측한다 — `git worktree add --detach <임시경로> <base>`로 base를 체크아웃해 같은 조건에서 재현되는지 확인한다(실측 예: PR #112 충돌 해결 후 테스트 5건 실패를 이 절차로 dev 기존 결함으로 갈라 별도 PR #115로 분리). 차단(🔴)은 **이 PR이 새로 만든 결함**에만 쓴다.
- **빌드/타입체크/테스트는 실행하지 않는다** — CI·컨트롤러 몫.

## 출력 형식 (심각도 4단계 · 2계층)
**심각도 4단계**: 🔴Critical(보안 결함·데이터 손실·프로덕션 중단 → merge 차단) · 🟠Major(명백한 버그·잘못된 로직·심각한 성능 → 수정 필수) · 🟡Minor(동작하나 개선 → 인라인 권고) · ⚪Nit(취향·스타일).

**심각도(영향도)와 확신도(진위)는 다른 축.** 요약은 한 코멘트, 지적은 **그 diff 라인에 인라인 앵커 + 코드블록**. 한 코멘트에 다 뭉치지 않는다(가독성).

**ⓐ 요약 코멘트 — 상단 1개, 불릿(산문 금지):**

> **꺾쇠 `<…>`는 전부 치환 대상이다.** 아래는 형식 견본이지 복붙할 내용이 아니다 — 검증 수치·판정·변경 항목은 **이 PR에서 실제로 나온 값**으로 바꾼다. 견본의 수치를 그대로 게시한 사고가 있었다(2026-07-27).

````markdown
## 🤖 자동 리뷰 (Codex adversarial)

**판정** <✅ Approve | 🟠 Request changes>  ·  **심각도** 🔴<n> 🟠<n> 🟡<n> ⚪<n>

**변경**
* <이 PR이 바꾼 것>
* <…>

✅ <이 PR에서 실제로 돌린 검증과 그 결과. 안 돌렸으면 왜 대상이 아닌지 쓴다>

**잘된 점**
* <짧게 — 없으면 생략>

**다음 액션** <한 줄. 무발견이면 "없음">
> 상세 지적은 아래 diff 라인 인라인 코멘트 참조.
````

**ⓑ 인라인 코멘트 — 발견별, diff 라인 앵커 + 코드블록:**
````markdown
🟠 **[Major]** 근무 중 순찰 시작 진입점이 앱 내 유일한데 제거됨 — 037 전까지 순찰 시작 UI 경로 부재.

**왜** `patrol` 탭(`router.dart:102`)은 아직 `PlaceholderScreen`.
**어떻게** 037 선행/동시 배포하거나 037 전까지 임시 진입점 유지.

```dart
// 현재 — work_card.dart:27-30
onTap: () => context.push(RoutePath.patrolProgress, extra: {'mode':'new'}),
```
````
- Critical·Major만 무엇/왜/어떻게 + **코드블록**. 코드블록 없는 "어떻게"는 금지(안 읽힌다). 수정이 명확하면 ` ```suggestion `으로(원클릭 적용).
- Minor·Nit은 한 줄: `⚪ **[Nit]** <무엇> → <어떻게>`. 같은 차원 Nit이 다수면 대표 2~3건 + "그 외 N건 생략".

## 재리뷰 — 수렴 판단
수정 후 재리뷰는 **발견이 실제로 줄 때만** 의미가 있다. 종결 조건이 없어 PR #74에서 6사이클이 돌았다.

- **사이클마다 발견 수(심각도별)를 요약에 남긴다** — 세지 않으면 수렴을 판단할 수 없다.
- **종결 — 하나라도 충족하면 멈춘다**: ⓐ 신규 Critical·Major 0건 · ⓑ 남은 발견이 전부 설계 범위 밖(미채택 결정 완료) · ⓒ 직전 사이클과 같은 지적 반복 · ⓓ 3사이클 경과 **且 남은 발견이 Minor·Nit뿐**.
- **ⓓ에 사이클 수만으로 걸지 않는다.** 2026-07-27 PR #93은 사이클 3에서 신규 [Major](새 조항이 스킬 본문에만 있어 생성된 계획 문서를 받는 실행자에게 전달되지 않음)가 나왔고, 사이클 수로 기계 종결했으면 반쪽짜리가 머지됐다 — 사이클 4에서 해소. **Critical·Major가 살아 있으면 ⓐ가 아직 성립하지 않은 것이다.** 무한 사이클은 ⓒ(같은 지적 반복)가 막는다.
- 멈출 때 **미채택 발견을 요약에 명시**한다 — 무시가 아니라 결정임을 남긴다.

## 게시 — 라인 앵커 (한 코멘트에 뭉치지 않기)
요약 1개 + 발견별 인라인을 **GitHub reviews API**로 한 번에:
```bash
# review.json = {"event":"COMMENT","body":"<ⓐ 요약 마크다운>",
#   "comments":[{"path":"lib/.../work_card.dart","line":30,"side":"RIGHT",
#     "body":"🟠 **[Major]** ...\n\n```dart\n...\n```"}, ...]}
owner_repo=$(gh repo view --json nameWithOwner -q .nameWithOwner)
gh api "repos/$owner_repo/pulls/<PR#>/reviews" --method POST --input review.json
```
- `line`(다중행이면 `start_line`+`start_side`+`line`)은 **diff에 존재하는 RIGHT 라인**만 가능. 없는 줄 지적은 comments에서 빼고 요약 body 하단에 `파일:라인`으로 짧게.
- 확신도 **≥0.8만** comments로. `path:line`은 엔진 출력의 file·line_start/end.
- 발견은 **컨트롤러가 차단/유지 평가** 후 사용자에게 요약.

## 하지 않는 것 (경계)
- 코드 **수정 안 함**(리뷰 전용). auto-merge·merge 차단 게이트 미도입(dry-run 우선 — 안전가드 통과 전).
- 자동 발화는 스킬이 아니라 **전역 CLAUDE.md 규칙**이 담당(스킬은 호출되는 쪽).
- 작성자 PR 설명 템플릿(Risk Score 입력)은 각 repo `.github/pull_request_template.md` 소관 — 스킬 밖.
